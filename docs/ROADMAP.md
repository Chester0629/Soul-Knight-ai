# Soul Knight 復刻 — 全局路線圖 (ROADMAP)

## 北極星與執行原則
- **終極目標**:完整可玩的元氣騎士 1:1 復刻(成品)。
- **執行策略**:北極星是「完整復刻」,但**永遠盯著下一個可玩里程碑**,
  不為終點做線性規劃。大型個人復刻熄火的主因是「目標訂在終點、中間無
  里程碑、熱情耗盡」——故拆成「每個停下都是完整可玩東西」的階梯。
- **三條組織原則**:
  1. 依賴驅動排序(前置沒好,後面接不上),不按難度。
  2. 每塊標性質:**建方法論**(精雕 + 關鍵環節掛 ultracode)vs
     **套方法論**(SOP 批量)。第一個同類精雕建 SOP,其餘批量。
  3. ultracode 只掛「有確定答案、可離線重算」的純邏輯;「遊戲內行為
     對不對」靠遊戲內驗,不掛 ultracode。

## 跨階段一貫紀律(從逆向到落地驗證有效,務必延續)
- 先確認事實再往下(讀 code 確認,不憑印象/慣例假設)。
- 窮盡而非列舉(「按名字搜不到 ≠ 不存在」;枚舉全集逐一判定)。
- 半吊子接線不假裝生效(如 floorIndex 雙重失效、isBossFloor 假 flag)。
- 條件性縫隙釘成顯式約束/測試,不留「latent 註記」。
- 範圍紀律:超出當前任務的全域/build 改動,先確認或收窄到最小 scope。
- 接縫處的隱含契約要顯式(如烤圖尺寸==sprite_rect、快照在 scene 死前捕捉)。
- 小步驗證再規模化(垂直切片/試金石先驗方法論)。
- 誠實標缺口,對不上如實報告不硬湊。

目標:單角色 + 初始武器 + 能打 + 清樓進下層 + 會死 + HUD + 技能能放。
量級:~15–25 輪。

- **A1 正向迴圈 (2a)** 【進行中】清空偵測+快照+轉場。精雕,遊戲內驗。
  - 命脈:快照必須在 Replace 銷毀 scene 前捕捉(deferred-op 時序)。
- **A2 失敗路徑 (2b)** 死亡→EndScene。依賴 A1。精雕,輕。
- **A3 CharSkill 接進 Player (b2)** 【關鍵前置,被低估】技能啟動+輸入
  綁定+cooldown 值可達。CharSkillC01-C13 brain 存在但未接進 Player。
  是 A4、B1b 的前置。精雕,掛 ultracode 驗 cooldown 邏輯。
- **A4 冷卻遮罩 (HUD Batch 2)** ui_joy_3 Filled。依賴 A3。Filled 渲染
  PTSD 沒有,需新建徑向/線性 fill。精雕。

**閉合點**:第一次玩到自己復刻的元氣騎士。到此停下校準里程碑二。

## 里程碑二:核心體驗完整(五臟俱全小遊戲)
目標:幾個角色可選 + 一批武器 + 商店能買 + 結算 + 基本關卡多樣性。
能放作品集、能給人玩。量級:里程碑一之上 ~60–120 輪(B1 佔大頭)。
關鍵轉變:從「接通機制」變「填內容 + 建內容方法論」。

- **B1 戰鬥內容方法論 + 第一批** 【最大塊,批量化成敗關鍵】
  - B1a 武器系統 SOP(逆向一把→重建的可重複流程)。精雕+建 SOP。
  - B1b 角色/技能 SOP。依賴 A3。精雕+建 SOP。
  - B1c 敵人 AI SOP。精雕+建 SOP。
  - B1d 批量套用「核心夠用」數量(非全部,全部留里程碑三)。批量,
    可掛 ultracode 驗數值。
  - 量級:本塊 ~30–50 輪。
- **B2 商店畫面** 第一個複雜互動畫面(ScrollRect+按鈕事件+動態內容)。
  精雕=建「複雜互動畫面 SOP」。買→BuyCoinN,IAP/Firebase stub。
  依賴 UI 方法論(已有)+ B3。
- **B3 經濟系統** 金幣/藍幣獲取持有消費。port 現在完全無。依賴 RunState。
  精雕,數值邏輯可掛 ultracode。
- **B4 結算畫面 (Statements)** 逆向規格已備(StateMents→Statements)。
  依賴 A2 + B3。UI 套 SOP,行為接逆向規格。
- **B5 角色選擇 (HeroRoom)** 角色資料展示+選擇→帶角色開 run。
  依賴 B1b + UI SOP。套 SOP。
- **B6 主選單 + 流程串接** Title→HeroRoom→run→結算→回選單。第一次串
  完整流程,#3a menu 子集在此。依賴 B5、B4。精雕,跨畫面狀態機是新東西。
- **B7 關卡多樣性(基礎)** 章節環境 + boss 樓層(%5 週期,當初 defer)+
  特殊房間(商店房/寶箱房)。依賴 A1。精雕生成邏輯+套用。

**閉合點**:Title 進入→選角→打→買→結算→通關/重來的完整小遊戲。

## 里程碑三+:完整內容填充(年計大頭,增量)
方法論已全建好,本質=用 SOP 批量填內容庫。
- 剩餘全角色/全武器/全敵人/全 boss(批量+boss 各自精雕)
- 剩餘全 UI(Exhibition/Certificate/Plutus 等 not-MVP 畫面,批量)
- buff/道具全集、解鎖/成就/元進度、存檔系統、全章節、平衡調校
- 性質:大部分 SOP 批量+ultracode 驗數值,少數精雕。
- **重要**:是否追到 1:1 全完整,到里程碑二玩到成品後再決定
  (那時才知道:對專案還有沒有熱情、「完整」是不是真需求)。

## 三個關鍵提醒
1. **A3 是早期關鍵前置**:唯一「機制全沒接、要建新 gameplay 架構」的塊,
   影響整個戰鬥系統批量化,值得精雕。
2. **B1 是批量化成敗賭注**:SOP 建得好,里程碑三輪數大幅壓縮;建不好則
   無限膨脹。三個「第一個」要精雕到 SOP 真可重複。
3. **SOP 化要顯式做成文件**:每建一套 SOP 固化成文件(武器移植 SOP、
   複雜互動畫面 SOP),是「個人+AI 復刻大遊戲」算術成立的核心槓桿。
